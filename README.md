## 🧭 The Story, End to End

**The question:** What does ApexPlanet's sales data tell us, and what should we do about it?

**Task 1 — Data Wrangling.** Started with 1,000 raw sales transactions. Found and fixed missing
values (2% of ages, 1.3% of cities) and a duplicate-ID bug affecting 9 transactions. Delivered a
clean, validated dataset with a full data dictionary.

**Task 2 — EDA & Business Intelligence.** Explored the cleaned data statistically and visually.
Found Electronics drives 36% of revenue from just 2 products. Built a normalized 3-table SQL
database and answered 7 real business questions using joins, filtering, and aggregation.

**Task 3 — Deep-Dive & Interactive Dashboarding.** Segmented all 947 customers using RFM
(Recency, Frequency, Monetary) analysis, identifying a high-value "At Risk" segment worth
targeting for win-back campaigns. Built a live, filterable dashboard (no BI tool license needed —
self-contained HTML/JS, hosted free on GitHub Pages).

**Task 4 — Data Storytelling & Statistical Validation.** Synthesized all findings into one
narrative and stress-tested the "obvious" assumptions with formal hypothesis testing (t-test,
chi-squared, ANOVA). All three came back non-significant — proving that customer _behavior_
(not demographics) is the real driver of spend, and validating the RFM-based strategy.

**The outcome:** a set of concrete, statistically backed recommendations — prioritize retention
over acquisition, target the "At Risk" segment specifically, and stop investing in
demographic-based targeting that the data doesn't support.

## 💡 Key Learnings

- **Clean data is a prerequisite, not a formality** — the duplicate-ID bug in Task 1 would have
  silently corrupted every downstream join and aggregation if left unfixed.
- **Statistical validation changes recommendations, not just confidence in them** — three
  "obvious" hypotheses (gender, city, price differences) all failed significance testing, which
  redirected the entire strategy toward behavioral segmentation instead of demographic targeting.
- **A dashboard only creates value if someone will actually open it** — building it as a
  self-contained, zero-install web app removed every friction point between "built" and "used."
- **The best insight is often a negative result** — "these three things don't matter" was more
  strategically useful than confirming something everyone already assumed.
